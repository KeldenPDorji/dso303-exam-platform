# Service documentation

Every service in the architecture, with the alternative it was chosen over and the configuration actually deployed
(file references point to the Terraform in [`infra/`](../infra)).

## Edge

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon Route 53** | Public DNS for the platform (`exams.<uni>.edu`). | Alias records point straight at CloudFront (no extra lookups, free alias queries, works at the zone apex) and the service has a 100% SLA. The university's on-premises DNS would be a single point of failure and has no alias support. | Optional: set `domain_name` + `hosted_zone_id`. A and AAAA alias records → CloudFront; DNS validation records for ACM ([edge.tf](../infra/edge.tf)). Without a domain, the CloudFront domain is used. | Users, CloudFront, ACM |
| **AWS Certificate Manager (ACM)** | TLS certificate for the custom domain. | Free, auto-renewing, private key never leaves AWS. A bought certificate or manual Let's Encrypt needs renewals that can lapse mid-semester. | Requested in `us-east-1` (CloudFront requirement), DNS-validated; CloudFront uses `TLSv1.2_2021` minimum with SNI. | CloudFront, Route 53 |
| **Amazon CloudFront** | Single HTTPS entry point: serves the SPA from edge caches and proxies `/api/*` to API Gateway. | Edge caching absorbs 3,000 simultaneous page loads that would otherwise hit the region. One origin for app and API means no CORS. It is the only place WAF can sit for both. Exposing S3 website hosting or API Gateway directly would give HTTP-only (S3 website) or no caching and no single WAF point. | Origins: private S3 via **Origin Access Control**, API Gateway (HTTPS only, adds secret `X-Origin-Verify` header). Default behaviour `CachingOptimized` + security headers; `/api/*` `CachingDisabled` + `AllViewerExceptHostHeader`; redirect HTTP→HTTPS; HTTP/2 + HTTP/3; IPv6; `PriceClass_All`. | Route 53, WAF, S3 frontend, API Gateway |
| **AWS WAF** | Layer-7 filtering in front of everything. | Security groups and NACLs only see IPs and ports, not HTTP. A self-managed WAF appliance would need servers in every AZ. AWS managed rule groups are maintained by AWS. | Web ACL scope `CLOUDFRONT` (us-east-1): Amazon IP reputation list, Common Rule Set (`SizeRestrictions_BODY` and `CrossSiteScripting_BODY` set to **count** so a long answer or an answer containing code is never blocked mid-exam), Known Bad Inputs, **rate limit 100,000 requests / 5 min per IP** (kept high because a whole exam hall can sit behind one NAT IP). CloudWatch metrics + sampled requests. | CloudFront, CloudWatch |
| **AWS Shield Standard** | Network/transport-layer DDoS protection. | Included free on CloudFront and Route 53. Shield Advanced (~US$3,000/month) is not justified for this risk level. | Automatic. | CloudFront, Route 53 |

## Frontend, identity and API

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon S3 (frontend bucket)** | Hosts the static single-page app (HTML/JS/CSS). | No web servers to patch or scale. EC2 + nginx would need an Auto Scaling group in two AZs for content that never changes between deploys. | Private, Block Public Access on, `BucketOwnerEnforced`, SSE-S3, bucket policy allows only this CloudFront distribution (`AWS:SourceArn`) and denies non-TLS. Deployed by `aws s3 sync` + CloudFront invalidation ([storage.tf](../infra/storage.tf)). | CloudFront, GitHub Actions |
| **Amazon Cognito (user pool)** | Role-based sign-in for students, tutors and admins. | Building auth into the app means storing password hashes and implementing MFA and recovery ourselves. Auth0/Okta add per-user cost and a third party holding student identities. Cognito issues JWTs that API Gateway validates natively, and federates with the university IdP (SAML/OIDC). | Email as username, **admin-create-only** (no self sign-up), 12+ character password policy, optional TOTP MFA (enforce for staff in production), groups `Admins`/`Tutors`/`Students` → `cognito:groups` claim. Public app client: **authorization code + PKCE**, no secret; ID token 60 min, refresh token 12 h, token revocation on ([auth.tf](../infra/auth.tf)). | SPA, API Gateway, API Lambda (admin user management) |
| **Amazon API Gateway (HTTP API)** | Front door of the API: authentication, throttling, routing to Lambda. | REST API costs ~3.5× more and its extra features (usage plans, request validation models) aren't needed. An ALB has no built-in JWT validation, bills hourly even when idle, and must sit in the VPC. | JWT authorizer (issuer = user pool, audience = app client). Routes `ANY /api/{proxy+}` (JWT) and `GET /api/health` (public). Stage throttling 1,500 rps steady / 3,000 burst; JSON access logs; Lambda proxy payload v2 to alias `live`; 15 s integration timeout ([api.tf](../infra/api.tf)). | CloudFront, Cognito, Lambda `api` |

## Compute

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **AWS Lambda: `api`** | All business logic: exams, autosave, submissions, presigned URLs, admin. | Scales per request with no capacity planning: it can add 1,000 concurrent executions every 10 s, so the 300 → 3,000-user spike needs no pre-warmed fleet. Between exam weeks it costs almost nothing. ECS Fargate or EC2 would need scheduled scale-out before each exam and pay for idle tasks the rest of the time. | Python 3.13 on **arm64** (Graviton, ~20% cheaper), 512 MB, 15 s timeout, **VPC private app subnets in both AZs**, alias `live` with optional **provisioned concurrency** for exam week (`api_provisioned_concurrency`), X-Ray active tracing, least-privilege IAM role, rejects requests without the CloudFront origin secret ([compute.tf](../infra/compute.tf)). | API Gateway, RDS Proxy, S3 (presign), SQS, Cognito, Secrets Manager, CloudWatch |
| **AWS Lambda: workers** (`processor`, `marker`, `notifier`, `migrate`) | Asynchronous processing: validate uploads, auto-mark MCQs, send email, apply DB schema. | Event-driven: runs only when there is work. A cron/worker EC2 instance would idle most of the year. Step Functions is unnecessary for single-step jobs. | SQS event source mappings with **maximum concurrency** caps (processor 10, marker 10, notifier 5) to protect the database and the SES rate; `ReportBatchItemFailures` (only failed messages are retried). `notifier` runs **outside the VPC** (no private resources needed, so no NAT dependency). `marker` also runs every 2 min from EventBridge to auto-submit expired attempts. | SQS, RDS Proxy, S3, SES, EventBridge |

## Network

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon VPC** | Private network isolating compute and data. | The default VPC has only public subnets, so the database could end up internet-routable (rubric "public database"). | `10.20.0.0/16`; per AZ (×2): public `/24`, private-app `/24`, private-data `/24`; data subnets have **no internet route**; VPC Flow Logs (REJECT) to CloudWatch ([network.tf](../infra/network.tf)). | everything in-VPC |
| **NAT gateway** (×2) | Outbound internet for Lambdas in private subnets (calls to SQS, Cognito, Secrets Manager, X-Ray). | A NAT instance is self-managed and a single point of failure. Interface endpoints for every service cost about US$15/month each across 2 AZs. | **One per AZ**, each private-app route table points to the NAT in its **own** AZ, so losing AZ A never breaks AZ B egress. `single_nat_gateway = true` only for a cheap lab run. | Internet gateway, private app subnets |
| **Internet gateway** | Internet access for the public subnets (NAT gateways only). | Required for NAT egress; no compute is placed in public subnets. | Attached to the VPC; public route table `0.0.0.0/0 → IGW`. | Public subnets |
| **VPC gateway endpoint (S3)** | Private path from Lambda to S3. | Going through NAT costs ~US$0.06/GB processing; the gateway endpoint is free and keeps traffic on the AWS network. | Associated with both private-app route tables. | Lambda, S3 |
| **Security groups** | Stateful firewall between tiers. | NACLs are stateless and subnet-wide; security groups can reference each other. | `lambda-sg`: egress 443 + 5432 → `proxy-sg`. `proxy-sg`: ingress 5432 from `lambda-sg`. `db-sg`: ingress 5432 **only from `proxy-sg`**. Nothing accepts traffic from the internet ([security.tf](../infra/security.tf)). | Lambda, RDS Proxy, RDS |

## Data and files

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon RDS for PostgreSQL (Multi-AZ)** | System of record: users, exams, questions, attempts (autosaved answers), marks, assignments, submissions. | **vs DynamoDB:** the data is relational (one attempt per student per exam, foreign keys, transactional exam creation, SQL reporting for tutors). **vs Aurora:** faster failover but roughly 2× the cost for a peak of only ~100 writes/s. **vs PostgreSQL on EC2:** patching, backups and failover would be manual. | PostgreSQL 16, **`multi_az = true`** (synchronous standby in AZ B, automatic failover), private data subnets, `publicly_accessible = false`, gp3 with storage autoscaling to 200 GB, **KMS-encrypted**, `rds.force_ssl = 1`, automated backups + **point-in-time restore** (7 days lab / 35 prod), master password **managed by RDS in Secrets Manager**, PostgreSQL logs to CloudWatch, deletion protection in prod. Lab size `db.t4g.small`, exam-week size `db.r6g.large` ([database.tf](../infra/database.tf)). | RDS Proxy, Secrets Manager, KMS, AWS Backup, CloudWatch |
| **Amazon RDS Proxy** | Connection pooling between Lambda and PostgreSQL. | Without it, hundreds of concurrent Lambda executions each open a connection and exhaust `max_connections` at peak. The proxy multiplexes them onto a small pool and holds client connections during a Multi-AZ failover, reconnecting to the new primary on the same endpoint. | `require_tls`, auth from the RDS-managed secret (SCRAM-SHA-256), `max_connections_percent 90`, borrow timeout 120 s, subnets in both AZs. | Lambda, RDS, Secrets Manager |
| **Amazon S3 (uploads bucket)** | Stores assignment files (PDF/ZIP ≤ 50 MB) for 5 years. | Cheaper and more durable (11 nines) than EBS/EFS. **Presigned POST** uploads keep 50 MB files off the API (API Gateway 10 MB / Lambda 6 MB limits) and let S3 enforce the size limit itself. | Versioning, **SSE-KMS** with the platform key + bucket key, Block Public Access, deny non-TLS, CORS `POST` from the site origin only. Presigned POST: `content-length-range 1–52,428,800`, exact `Content-Type`, 15-min expiry, server-chosen key. **Lifecycle:** 30 d → Standard-IA, 180 d → Glacier Instant Retrieval, 365 d → Deep Archive, expire 1,830 d; non-current versions 90 d; abort incomplete multipart 1 d. Event notification `ObjectCreated` → SQS. | Browser, Lambda (api, processor), SQS, KMS, CloudTrail |

## Asynchronous processing

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **Amazon SQS (+ dead-letter queues)** | Buffers work: `submissions` (S3 events), `marking`, `notifications`. | Synchronous processing would hit the DB and SES with 3,000 submissions at the deadline at once. SNS alone has no buffer or back-pressure. Kinesis adds ordering/stream semantics we don't need. | SSE-SQS encryption, 20 s long polling, visibility timeout 6× the consumer timeout, `maxReceiveCount 5` → DLQ (14-day retention) with a CloudWatch alarm; submissions queue policy only accepts our bucket (`aws:SourceArn`) ([async.tf](../infra/async.tf)). | S3, Lambda workers, API Lambda, CloudWatch |
| **Amazon EventBridge (scheduled rule)** | Runs the exam sweeper every 2 minutes. | A cron job on EC2 means a server to keep alive; the scheduled rule is serverless. | `rate(2 minutes)` → `marker` with `{"sweep": true}`: auto-submits attempts past deadline + 60 s grace and re-queues any attempt left unmarked for 10 min. | Lambda marker |
| **Amazon SES** | Transactional email: submission receipts, tutor alerts, results released. | SNS email can't address individual students with custom content, and every recipient must confirm a subscription. SendGrid/Mailgun would be another processor of student data. | Verified sender identity (production: verified university domain with DKIM/SPF/DMARC and SES production access); SESv2 `SendEmail`; emails contain **no grades**, only a link (privacy). | Lambda notifier |

## Security, monitoring and operations

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **AWS Secrets Manager** | Holds the database credentials. | Environment variables leak into consoles and logs. SSM Parameter Store has no built-in RDS rotation. | Secret **created and rotated by RDS** (`manage_master_user_password`), encrypted with the platform KMS key; Lambda caches it and re-reads on auth failure; RDS Proxy reads the same secret. | RDS, RDS Proxy, Lambda, KMS |
| **AWS KMS (customer-managed key)** | Encryption at rest. | AWS-managed keys can't have their key policy changed, disabled or shared. A CMK gives control, annual rotation and CloudTrail-audited use. | Automatic rotation on, 7-day deletion window. Encrypts RDS storage, the DB secret, the S3 uploads bucket and the backup vault. | RDS, S3, Secrets Manager, AWS Backup, Lambda |
| **AWS IAM** | Least-privilege access everywhere. | One shared "app" role or IAM user access keys would mean one leak exposes everything. | One role **per Lambda** (e.g. `notifier` can only `ses:SendEmail` and read its queue; `processor` can only read `submissions/*`). GitHub uses an **OIDC identity provider** + deploy role restricted to this repo's `main`/`production`/PR. No long-lived keys anywhere. | all services, GitHub Actions |
| **Amazon CloudWatch** | Logs, metrics, alarms and the exam-day dashboard. | Self-hosted Prometheus/Grafana/ELK would need its own HA servers; CloudWatch is native and zero-ops. | Log groups (30-day retention) for every Lambda, API access logs, RDS, VPC Flow Logs. **Alarms:** API 5xx, p99 latency > 2 s, Lambda errors/throttles, DLQ not empty, marking backlog > 5 min, DB CPU > 80%, free storage < 2 GB → SNS. **Dashboard:** requests, latency, Lambda concurrency, DB CPU/connections, queue depth ([monitoring.tf](../infra/monitoring.tf)). | all services, SNS |
| **AWS X-Ray** | Distributed tracing. | Logs alone don't show where latency comes from during the peak (API Gateway vs Lambda vs DB). | Active tracing on every Lambda. | API Gateway, Lambda |
| **Amazon SNS (alerts topic)** | Delivers alarm notifications to the on-call team. | CloudWatch alarms can only notify through SNS (or other integrations). | Email subscription from `alarm_email`. | CloudWatch alarms |
| **AWS CloudTrail** | Audit trail of every API call, plus **S3 data events** on the uploads bucket (who uploaded/downloaded which submission). | The default 90-day event history is too short for 5-year records and has no data events. | Multi-region trail, log file validation, S3 bucket with lifecycle → Glacier at 90 d, kept 1,830 d. | S3 (audit bucket), all services |
| **AWS Backup** | Long-term database backups for 5-year retention. | RDS automated backups stop at 35 days, and manual snapshots get forgotten. | Vault encrypted with the CMK; plan: daily backups kept 35 d + **monthly kept 1,830 d**; selection = the RDS instance ([backup.tf](../infra/backup.tf)). Production: add a cross-region copy and Vault Lock. | RDS, KMS |

## Delivery

| Service | Role | Why over an alternative | Configuration | Connects to |
|---|---|---|---|---|
| **GitHub Actions** | CI/CD pipeline. | The code is already on GitHub (submission requirement), Actions has free minutes and native OIDC to AWS. CodePipeline + CodeBuild would add a second place to manage pipelines. | PR: unit + integration tests, `terraform fmt/validate`, `terraform plan`. **Push to `main`:** tests → build layer → `terraform apply` → S3 sync + CloudFront invalidation → migrate Lambda → smoke test through CloudFront. `production` environment, concurrency group (never two applies at once) ([deploy.yml](../.github/workflows/deploy.yml)). | GitHub repo, IAM OIDC role, AWS |
| **Terraform** | Infrastructure as code for every resource. | Console-built infrastructure isn't reproducible. CloudFormation/CDK can't manage the `us-east-1` WAF/ACM resources in the same stack as cleanly as provider aliases. `terraform plan` shows the exact diff on each PR. | AWS provider 6.x; remote state in a versioned, encrypted S3 bucket with **native lockfile**; one-time `infra/bootstrap` creates the state bucket and the GitHub OIDC role. | AWS, GitHub Actions |
